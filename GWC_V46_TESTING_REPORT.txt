GWC V46 CLOUD SYNC OPTIMIZATION – LOCAL VALIDATION REPORT

Changes:
- index.html: changed cloud polling from repeated full-state fetches to lightweight revision polling every 3 seconds; full state is fetched only when revision changes. Save response revision is tracked. Polling is paused in hidden tabs and defers applying remote state while a form/input is actively edited.
- Code.gs: added lightweight readStateMeta_() and GET loadmeta metadata response; normal load and write/chunk/backup safeguards remain in place. Save response now returns revision.
- server.js, package.json, appsscript.json and all other existing application files retained unchanged.

Checks performed locally:
- ZIP extraction and original archive listing reviewed.
- Node syntax check: server.js.
- Node syntax check: Code.gs copied to a .js check file.
- Node syntax check: all 30 inline JavaScript blocks in index.html.
- JSON parse: package.json and appsscript.json.
- Existing source files retained; only index.html and Code.gs are modified among existing app sources, plus this V46 README/report are added.

Not tested here:
- Live Render deployment and live Google Apps Script/Sheets read-write round trip.
- Real simultaneous Admin/Teacher/Sub-admin/Student accounts or Android/PC devices.
- Google Apps Script quota/latency under the actual number of concurrent users.

Expected result: cross-role updates should normally be detected within approximately one 3-second polling interval plus Google/Render network and Apps Script response time. This is not a guarantee of a fixed end-to-end sync time.
