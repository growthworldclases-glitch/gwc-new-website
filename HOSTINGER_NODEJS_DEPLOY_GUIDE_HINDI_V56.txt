GROWTH WORLD CLASSES — HOSTINGER NODE.JS WEB APP DEPLOY GUIDE (V56)

IMPORTANT COMPATIBILITY
- यह ZIP एक Node.js + Express backend website है (package.json + server.js).
- Hostinger के Business/Unlimited और Cloud plans Node.js Web Apps support करते हैं. आपका Unlimited plan dashboard में Web App option दिखाए तो यही ZIP deploy किया जा सकता है.
- इसे केवल PHP/HTML upload करके public_html में extract न करें. Hostinger Dashboard → Websites → Create site → Web App चुनें.
- Existing live website/domain को हटाने या replace करने से पहले पूरा backup लें. Hostinger के current workflow में Node.js website को Web App के रूप में create करना होता है; existing PHP/WordPress site को सीधे in-place Node app में switch करने की कोशिश न करें.
- Hostinger official docs: https://www.hostinger.com/support/how-to-deploy-a-nodejs-website-in-hostinger/

ZIP ROOT
Extracted project root में package.json, server.js, index.html, public/index.html, Code.gs और assets मौजूद होने चाहिए. ZIP के अंदर किसी nested subfolder को Root directory न बनाएं.

HOSTINGER DEPLOYMENT
1. Existing website, Google Sheet, Drive, Apps Script project, DNS records और current files का backup लें. Live old website को तब तक बंद न करें जब तक नया app login/sync test पास न कर ले.
2. Hostinger hPanel → Websites → Create site → Web App पर जाएँ.
3. Domain के रूप में growthworldclasess.com चुनें. यदि Hostinger कहे कि domain पहले से existing website पर attached है, तो पहले backup लेकर Hostinger के official Node.js migration/create flow का पालन करें; existing site/email delete करने का फैसला बिना backup न करें.
4. “Upload your files” चुनें और GWC_HOSTYCARE_DOMAIN_SECURE_V56.zip upload करें.
5. Framework preset में Express चुनें (यदि auto-detect हो तो Express confirm करें). Node version 20.x चुनें. Project root ZIP ka root/project root हो.
6. Build/package manager npm चुनें. Hostinger dependencies install/build करे. यदि “Other” preset मिले तो Entry file = server.js सेट करें; Build command blank/None रखें यदि Hostinger कोई build step नहीं माँगता. package.json में start script `node server.js` पहले से मौजूद है.
7. Environment Variables में ये दो variables add करें:
   GWC_API_URL = आपके मौजूदा Google Apps Script Web App का पूरा /exec URL
   GWC_API_SECRET = कम-से-कम 32 characters का random secret (64 random hex characters बेहतर).
   असली URL और secret केवल Hostinger Environment Variables में डालें. उन्हें ZIP, GitHub, HTML, chat या screenshots में सार्वजनिक न करें.
8. Apps Script project खोलें → Project Settings → Script Properties. GWC_API_SECRET नाम की property बनाएँ और Hostinger के secret के बिल्कुल समान value डालें.
9. ZIP का नया Code.gs अपने मौजूदा Apps Script project में update करें. बाकी existing project files/functions और Script Properties (जैसे GWC_SPREADSHEET_ID, GWC_DRIVE_FOLDER_ID) न हटाएँ. Deploy → Manage deployments → existing Web App deployment Edit → New version → Execute as Me → access Anyone → Deploy. Existing deployment URL/ID बनाए रखें ताकि GWC_API_URL न बदले.
10. अलग पुराने Apps Script deployments यदि पहले की ZIPs के लिए सक्रिय हैं तो नए authenticated deployment का test करने के बाद Deploy → Manage deployments में पुराने अलग deployment IDs को disable/archive करें. केवल इस ZIP से अलग deployment बंद नहीं हो सकता.
11. Hostinger में Environment Variables save करके app deploy/redeploy करें. Domain पर HTTPS/SSL active होना चाहिए.
12. https://growthworldclasess.com/healthz खोलें. JSON में `ok:true` आना चाहिए. फिर Admin, Teacher, Student, Subadmin login और non-critical test save/read करें.

V56 PUBLISH / SYNC
- Admin dashboard में “Publish Now” button current state को authenticated Google Apps Script backend पर तुरंत save करता है.
- दूसरे खुले portals cloud state हर 60 seconds में check करते हैं. Remote state बदली हो तो UI/state update होता है; page का full reload नहीं होता.
- Local unsaved edits, open forms और active save के दौरान remote update apply नहीं किया जाता, ताकि typing/unsaved work overwrite न हो.
- यह WebSocket/push नहीं है. Admin का publish request complete होने के बाद दूसरे portal सामान्यतः अगले successful 60-second poll में update होंगे; zero-delay delivery की guarantee नहीं है.
- Hostinger shared Node.js hosting inbound WebSockets और always-running background workers support नहीं करती. इस ZIP को WebSocket/worker की जरूरत नहीं; यह normal Express request handling + browser polling use करता है.

DOMAIN / SECURITY
- Website/API host allowlist केवल exact `growthworldclasess.com` को accept करती है. `www.growthworldclasess.com`, temporary Hostinger URL और दूसरे lookalike domains को 403 मिलेगा. यदि www इस्तेमाल करना हो तो उसे website host की तरह enable न करें; DNS/hosting पर apex domain पर redirect configure करें.
- Apps Script पर हर GET/POST के लिए private GWC_API_SECRET जरूरी है. पुरानी ZIP उसी Apps Script deployment URL से बिना secret request करेगी तो Unauthorized मिलेगी.
- Apps Script “Anyone” setting जरूरी है क्योंकि Hostinger server Google को server-to-server call करता है; वास्तविक authorization secret check से होती है.
- Origin/Referer/Host checks अकेले cryptographic identity नहीं हैं. Apps Script secret मुख्य backend protection है. Secret को public न करें; leak हो तो Hostinger और Apps Script दोनों जगह rotate करें.
- अलग पुराने Apps Script deployment IDs active रहने पर उन्हें manually disable करना जरूरी है. Old deployment disable किए बिना पुराने अलग URL पर पुरानी ZIP अभी भी connect कर सकती है.

POST-DEPLOYMENT TEST CHECKLIST
[ ] /healthz returns ok:true
[ ] https://growthworldclasess.com opens with HTTPS
[ ] /api/gwc?action=load returns JSON (browser same-origin)
[ ] Admin login works with existing ID/password
[ ] Teacher, Student, Subadmin login work with existing credentials
[ ] Existing students/courses/fees/batches remain present
[ ] One non-critical test save and reload/read succeeds
[ ] Admin Publish Now appears and saves
[ ] Another browser/device sees the changed data within about 60 seconds
[ ] Lookalike hostname and www host return 403 (www should redirect at DNS/hosting if configured)
[ ] Old same-deployment direct Apps Script call without secret returns Unauthorized
[ ] Separate obsolete Apps Script deployments are disabled

DO NOT DELETE OLD HOSTING / GOOGLE DATA
Old hosting, old ZIP, Google Sheet and Drive backups ko tab tak preserve karein jab tak all tests pass na ho jaayen. Is ZIP ko banane ke dauran Hostinger account, DNS, Apps Script, Google Sheets/Drive ya real user logins par live end-to-end test nahi kiya gaya.
