GROWTH WORLD CLASSES — V52 CLOUD RUN DEPLOYMENT GUIDE (HINDI)

इस V52 पैकेज में V51 की application files नहीं बदली गई हैं। केवल यह deployment guide जोड़ी गई है। V51 server.js पहले से PORT, 0.0.0.0, /healthz, Express compression, static assets और Apps Script proxy support करता है। पुराने features, credentials, Sheets/Drive और Apps Script logic को सुरक्षित रखने के लिए code change नहीं किया गया।

1) BACKUP और GITHUB
• V51 ZIP की backup copy रखें। Railway अभी बंद न करें। ZIP extract करें और files/folders repository के ROOT में upload करें; server.js और package.json root में हों और public/ पूरा रहे।
• Repository को Public न करें: inherited wrangler.toml में Apps Script endpoint मौजूद है। Public repo में secrets/config उजागर हो सकते हैं। GWC_API_URL को Cloud Run में Secret Manager से configure करें।

2) GOOGLE CLOUD PROJECT
• https://console.cloud.google.com/ खोलें, project बनाएं/चुनें और billing account link करें।
• APIs enable करें: Cloud Run Admin API, Cloud Build API, Artifact Registry API.

3) CLOUD RUN — GITHUB SOURCE DEPLOY
• Cloud Run → Create service → Continuously deploy from a repository / Source repository. GitHub connect करके GWC repo और main branch चुनें।
• Build type: Node.js via Google Cloud Buildpacks. Build context: repository root (/). Entrypoint खाली रखें ताकि package.json का npm start चले। Dockerfile आवश्यक नहीं है।
• Service name: gwc-website. Region: asia-south1 (Mumbai). Authentication: Allow unauthenticated invocations (public student/parent website के लिए)।
• शुरुआती configuration: CPU 1; Memory 512 MiB (OOM दिखे तो 1 GiB); Request-based billing; Minimum instances 0; Maximum instances 2. Concurrency default रहने दें। वास्तविक peak load test के बिना 100/200 concurrent users की guarantee नहीं है।
• Port default रहने दें; app Cloud Run के PORT environment variable पर सुनता है। Health endpoint: /healthz.

4) GWC_API_URL SECRET (बहुत जरूरी)
• Secret Manager → Create secret → नाम GWC_API_URL. Value में अपना मौजूदा Google Apps Script Web App का पूरा /exec URL डालें।
• Cloud Run service → Edit and deploy new revision → Variables & Secrets → Reference a secret. Environment variable: GWC_API_URL; Secret: GWC_API_URL; Version: latest (या चुना हुआ version)।
• Cloud Run service identity को Secret Manager Secret Accessor permission दें। URL को GitHub/source code या screenshots में न डालें। Apps Script deployment permissions वही रखें जो अभी working website में हैं।

5) TESTS — RAILWAY बंद करने से पहले
• Cloud Run URL पर homepage खोलें। URL + /healthz पर JSON ok:true आना चाहिए।
• मौजूदा Admin, Teacher, Student IDs/password से अलग-अलग login करें; कोई credential reset न करें।
• Sheets read/write, fee records, homework/tests, doubts/notes, Drive uploads (एक 1MB से बड़ा upload भी) और Meet links test करें।
• दो devices पर simultaneous login और 10–20 test sessions चलाएं। 100/200 students की peak concurrency अलग से load-test करनी होगी। Logs में 5xx, timeout, OOM और Apps Script errors देखें।
• कोई test fail हो तो Railway active रखें और DNS/domain switch न करें।

6) BILLING / COST CONTROL
• Request-based billing और minimum instances 0 रखें। Minimum instances चालू होने पर idle charges हो सकते हैं।
• Budgets & alerts में उदाहरण के लिए ₹300, ₹500, ₹800 thresholds बनाएं। Budget alerts खर्च को रोकते नहीं हैं; hard spending cap नहीं हैं।
• Cloud Run free tier की eligibility/limits monthly billing account usage पर निर्भर हैं। Mumbai asia-south1 Tier 1 region है, लेकिन Internet egress अलग charge हो सकता है। North America की 1 GiB networking allowance को Mumbai traffic के लिए free न मानें। Cloud Build, Artifact Registry storage और logs के charges भी संभव हैं।
• Current pricing: https://cloud.google.com/run/pricing
• Source deployment: https://docs.cloud.google.com/run/docs/deploying-source-code
• GitHub continuous deployment: https://docs.cloud.google.com/run/docs/continuous-deployment

7) DOMAIN SWITCH / ROLLBACK
• पहले generated Cloud Run URL पर सभी tests pass करें। DNS records का backup/screenshot लें; उसके बाद ही custom domain/DNS बदलें।
• Railway service, environment variables और deployment delete न करें। Cloud Run fail हो तो DNS पुराने Railway target पर वापस करें। Sheets/Drive backend अलग से migrate नहीं हो रहा।

STATUS / LIMITATIONS
यह offline package है। Google Cloud project creation, GitHub connection, live deployment, billing, custom domain, Apps Script end-to-end testing और 100/200-student load test इस package से स्वतः नहीं हुए हैं। Actual cost traffic, outbound GB, builds, logs और region पर निर्भर है।
