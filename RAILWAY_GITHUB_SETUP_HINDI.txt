GWC V49.3 — RAILWAY + GITHUB DEPLOYMENT PACKAGE
================================================

यह ZIP आपके दिए हुए GWC_V49_3_ADMIN_CLASS_TIMINGS_CANDIDATE.zip पर आधारित है।
मौजूदा HTML, Code.gs, Apps Script, assets, package.json और बाकी सभी मूल archive
files रखे गए हैं। Railway के लिए केवल railway.json, .env.example, .gitignore
जोड़े गए हैं और server.js में Railway के PORT पर 0.0.0.0 bind स्पष्ट किया गया है।

महत्वपूर्ण: इस पैकेज में GWC की मुख्य application state अभी भी उसी मौजूदा
Google Spreadsheet (GWC_Storage) में रहती है। Google Drive attachments, files,
archive और Workspace operations के लिए इस्तेमाल होता है। इस ZIP ने state को
Drive में migrate नहीं किया है, क्योंकि बिना verified migration ऐसा करना
accounts, fees, courses और assignments को जोखिम में डाल सकता है।
Railway पर कोई database या persistent volume आवश्यक नहीं है।

सबसे जरूरी डेटा-सुरक्षा नियम
-----------------------------
1. वही पुराना Apps Script project इस्तेमाल करें।
2. वही पुराना GWC_SPREADSHEET_ID और GWC_DRIVE_FOLDER_ID Script Properties रखें।
3. मौजूदा Google Spreadsheet या Drive folder को delete/replace न करें।
4. Apps Script deployment URL वही रखें। केवल तब नया deployment करें जब Code.gs
   में बदलाव हो; इस Railway package में Code.gs नहीं बदला गया है।
5. GitHub पर वास्तविक .env, passwords, spreadsheet IDs या private records commit
   न करें। GWC_API_URL को Railway Variables में डालें।
6. पहले test deployment करें; पुराने hosting को verification तक बंद न करें।

PART A — GitHub में ZIP अपलोड करना
----------------------------------
1. https://github.com खोलें और login करें।
2. ऊपर + > New repository चुनें।
3. Repository name: gwc-website-railway
4. Private चुनें (सिफारिश), फिर Create repository।
5. Add file > Upload files चुनें।
6. इस ZIP को अपने PC पर Extract करें।
7. Extracted folder के अंदर की सभी files/folders upload करें। ZIP file को अकेले
   upload न करें। सुनिश्चित करें कि package.json, server.js, index.html,
   Code.gs और railway.json repository के root में हों।
8. Commit changes दबाएँ।
9. GitHub repository में जाँचें कि root पर package.json और server.js दिख रहे हैं।

PART B — Railway में GitHub connect करना
----------------------------------------
1. https://railway.com खोलें और login करें।
2. Hobby plan चुनें। आधिकारिक plan $5/month minimum है और $5 monthly usage
   शामिल करता है; अधिक usage पर extra bill हो सकता है।
3. Dashboard > New Project > Deploy from GitHub Repo चुनें।
4. GitHub access authorize करें और gwc-website-railway चुनें।
5. Railway को repository build करने दें। package.json में start script
   "node server.js" है; अलग database service न जोड़ें।
6. Service > Variables में जाएँ।
7. Variable जोड़ें:
   Name: GWC_API_URL
   Value: आपकी मौजूदा Google Apps Script Web App URL, जो /exec पर समाप्त होती है।
   उदाहरण का placeholder इस्तेमाल न करें; अपना वास्तविक पुराना URL डालें।
8. Save/Deploy करें। Railway PORT अपने आप देता है; PORT manually set न करें।
9. Settings > Networking में Generate Domain दबाएँ।
10. Railway public URL खोलें। /healthz जोड़कर health check करें:
    {"ok":true,"service":"GWC website proxy",...}
11. अगर build fail हो तो Deployments > View Logs देखें। Root directory गलत हो
    तो सुनिश्चित करें कि package.json repository root पर है।

PART C — Go-live से पहले परीक्षण
--------------------------------
पहले Railway generated URL पर ये सभी checks करें:
1. Admin login — वही पुराना ID/password।
2. Sub-admin, Teacher और Student login।
3. Course Store और course order।
4. Student assignments और teacher batch/course view।
5. Fee records, fee cycle, fee slip और reminders।
6. Join My Class / Google Meet।
7. Google Drive upload/download/archive।
8. Google Workspace spreadsheet open/create (Admin verification सहित)।
9. Admin Class Timings।
10. Logout/login और browser refresh के बाद cloud data मौजूद है या नहीं।

किसी भी data mismatch, login issue या API error पर पुराने live URL को चालू रखें
और Railway URL को public users को न दें। पुरानी hosting तभी retire करें जब
production checks पूरे हों और backup सत्यापित हो।

PART D — Custom domain
----------------------
1. Railway service > Settings > Networking > Custom Domain।
2. अपना domain/subdomain जोड़ें और Railway द्वारा दिए DNS records अपने DNS
   provider में set करें।
3. DNS verify और HTTPS certificate ready होने के बाद ही public URL बदलें।
4. Domain बदलने पर Apps Script/Google APIs में redirect/origin assumptions हों
   तो अलग से जाँचें। इस package में domain-lock security नहीं जोड़ी गई है।

PART E — Rollback
-----------------
यदि Railway deployment में समस्या आए:
1. पुराने hosting deployment को delete न करें।
2. DNS को पुराने working hosting पर वापस रखें या users को पुराने URL पर भेजें।
3. Google Sheet / Apps Script properties में कोई नया blank spreadsheet न बनाएँ।
4. Railway deployment rollback करें या GitHub में previous commit restore करें।

COST CONTROL
------------
- Railway Hobby $5 minimum monthly usage commitment है; included usage $5 है।
- Extra CPU/RAM/egress/storage usage पर bill बढ़ सकता है।
- Railway पर PostgreSQL/Redis या Volume इस build के लिए न जोड़ें।
- Static assets GitHub deployment से serve होंगे; application state Google Sheets
  और file storage Google Drive/Apps Script में ही रहेंगे।
- Railway dashboard में Usage/Billing नियमित जाँचें।

सुरक्षा नोट
-----------
V23 baseline के अनुसार यह proxy website-origin/domain lock लागू नहीं करता।
सिर्फ browser Origin/Referer header पर भरोसा करके Apps Script endpoint सुरक्षित
नहीं माना जा सकता। Public Apps Script /exec endpoint को सीधे call किया जा सकता
है। इसलिए इस ZIP को "domain restricted" या "fully secure" न मानें। मजबूत
server-verifiable authentication के लिए अलग coordinated proxy + Apps Script
security change और end-to-end testing चाहिए; वह इस controlled Railway packaging
में नहीं किया गया है।

ऑफलाइन जाँच की सीमा
-------------------
ZIP integrity, JSON parsing और JavaScript syntax जाँचे जा सकते हैं। इस environment
से आपके GitHub, Railway, Google account, live spreadsheet या live Apps Script
पर login/deploy/Drive write test नहीं किया गया है। इसलिए live success की guarantee
नहीं दी जा रही।
