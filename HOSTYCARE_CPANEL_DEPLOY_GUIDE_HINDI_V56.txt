GROWTH WORLD CLASSES — HOSTYCARE cPANEL / NODE.JS DEPLOYMENT GUIDE (V56 DOMAIN + API LOCK + 60-SECOND PUBLISH)

HOSTING COMPATIBILITY
यह ZIP Node.js + Express application है; PHP-only hosting पर सीधे नहीं चलेगा।
HostyCare account में cPanel का “Setup Node.js App” / “Node.js Selector” उपलब्ध होना जरूरी है।
Node.js 20 (या कम-से-कम 18), Production mode, startup file server.js चुनें।

ZIP में जरूरी फाइलें
- package.json — npm start और dependencies
- server.js — HostyCare Node.js entry point, domain allowlist और private Google proxy
- index.html तथा public/index.html — दोनों मौजूदा website entry copies
- Code.gs — Google Apps Script backend; इसे cPanel में upload करके Node app की तरह run नहीं करना है
- appsscript.json — Apps Script manifest
- worker.js / wrangler.toml — वैकल्पिक Cloudflare deployment; HostyCare Node.js के लिए आवश्यक नहीं
- assets/ — मौजूदा website asset files

HOSTYCARE DEPLOYMENT
1. पहले ZIP, GitHub repository, Google Sheet, Drive और Apps Script project का backup लें।
2. cPanel में Setup Node.js App खोलें। Application root को public_html से बाहर अलग folder रखें, जैसे /home/CPANEL_USER/gwc-node-app.
3. ZIP को extract करें ताकि package.json और server.js सीधे Application root में हों (किसी nested folder में नहीं)।
4. Node.js 20 चुनें; Application mode Production; Startup file server.js; Application URL में केवल growthworldclasess.com चुनें। www subdomain को app पर अलग host की तरह serve न करें; जरूरत हो तो DNS/hosting स्तर पर apex domain पर redirect करें।
5. Run NPM Install करें। फिर cPanel Environment Variables में नीचे के दो variables add करें:
   GWC_API_URL = आपके मौजूदा Google Apps Script Web App का पूरा /exec URL
   GWC_API_SECRET = कम-से-कम 32 characters का random secret (64 random hex characters बेहतर; terminal में openssl rand -hex 32 से बना सकते हैं)
   दोनों values को ZIP, HTML, GitHub या public screenshot में न डालें।
6. Apps Script project खोलें: Project Settings -> Script Properties -> Add script property.
   Property name: GWC_API_SECRET
   Value: HostyCare में GWC_API_SECRET के बिल्कुल समान secret.
   Save करें।
7. Apps Script editor में ZIP का नया Code.gs code अपने मौजूदा project में update करें। बाकी project files/functions को हटाएँ नहीं। फिर Deploy -> Manage deployments -> अपने मौजूदा Web App deployment को Edit करें, Version में New version चुनें, Execute as Me और access setting Anyone रखें, और Deploy करें। Existing deployment URL/ID को यथासंभव unchanged रखें ताकि GWC_API_URL न बदले।
8. यदि पुराने Apps Script deployments अलग IDs/URLs کے ساتھ فعال ہیں تو Deploy -> Manage deployments میں ان پرانے غیر استعمال شدہ deployments کو Disable/Archive کریں۔ صرف نئے authenticated deployment کو فعال رکھیں۔ ऐसा करने से पहले नए backend को test करें।
9. cPanel में Save/Apply और Restart Application करें।
10. Deploy के बाद project root में `npm test` चलाएँ; 19/19 offline checks PASS होने चाहिए। फिर https://growthworldclasess.com/healthz खोलें। इसके बाद website login और Google sync test करें। केवल https://growthworldclasess.com/ को canonical website रखें और SSL enabled हो। www को अलग website के रूप में allow न करें; चाहें तो उसे apex पर redirect करें।

SECURITY का वास्तविक अर्थ / जरूरी सीमाएँ
- Node server केवल growthworldclasess.com Host header और उसी exact HTTPS Origin/Referer को स्वीकार करता है; www सहित दूसरे hostnames को 403 मिलेगा।
- Browser API routes same-origin Origin/Referer मांगते हैं। यह सामान्य cross-site browser use को रोकता है; अकेले Origin/Referer cryptographic security नहीं हैं।
- Google Apps Script अब हर GET/POST पर private GWC_API_SECRET मांगता है। Secret केवल HostyCare server environment और Apps Script Script Properties में रहता है; browser HTML में नहीं।
- पुरानी ZIP में पुराना Google Script URL होने के बावजूद, उसी Apps Script deployment को नए authenticated Code.gs के साथ redeploy करने पर बिना secret की पुरानी requests reject होंगी।
- यदि पुरानी ZIP किसी अलग पुराने Apps Script deployment URL का उपयोग करती है, तो उस पुराने deployment को अलग से Disable करना जरूरी है। केवल नई ZIP से पुराने अलग deployment को बंद नहीं किया जा सकता।
- कोई भी public website endpoint पूर्णतः “केवल domain” पर cryptographic रूप से सीमित नहीं होता: non-browser caller Host/Origin headers spoof कर सकता है। यह बदलाव पुराने clients और सामान्य cross-origin browser access को रोकता है, लेकिन पूर्ण user authentication, rate limiting, abuse protection और per-role backend authorization का विकल्प नहीं है।
- Google Apps Script deployment का access “Anyone” रहना आवश्यक है क्योंकि HostyCare server Google से server-to-server request करता है; सुरक्षा Script Properties वाले secret से enforce होती है।
- Secret को भूलें/लीक होने पर HostyCare और Apps Script दोनों जगह rotate करें।

POST-DEPLOYMENT TEST
- Project root में `npm test` चलाकर offline regression suite पास करें; विस्तृत परिणाम GWC_V57_OFFLINE_REGRESSION_REPORT_HINDI.txt में है। यह live test का विकल्प नहीं है।
- Admin, Teacher, Student, Subadmin के मौजूदा Login ID/Password से login करें; कोई credential reset न करें।
- Google Sheet load और एक non-critical test save/read करें।
- Assigned Students, courses, batches, fee records/slips, homework, tests, doubts, Help Desk, private notes और Drive upload test करें।
- दूसरे hostname पर website खोलने पर 403 आना चाहिए।
- पुराने client से Apps Script endpoint को बिना gwc_auth / _gwcAuth call करने पर Unauthorized आना चाहिए।
- सभी tests पास होने तक पुरानी live hosting बंद न करें और DNS switch न करें।

IMPORTANT
V56 में Admin का “Publish Now” बटन current state को तुरंत Google Sheet backend पर save करता है। दूसरे खुले हुए portals अधिकतम लगभग 60 seconds में guarded check करते हैं और केवल वास्तविक remote बदलाव मिलने पर state/UI update करते हैं; पूरा webpage reload नहीं होता। Polling तभी काम करेगी जब सभी portals इसी V56 canonical domain पर खुले हों और backend reachable हो। यह server push/websocket नहीं है, इसलिए zero-delay delivery की guarantee नहीं है।

यह ZIP offline source validation के लिए तैयार किया गया है; इसे आपके HostyCare account में deploy नहीं किया गया है। HostyCare plan में Node.js enablement, DNS, SSL, environment variables, Google Apps Script deployment और live login/Drive/Sheets tests account-level पर करने होंगे।
