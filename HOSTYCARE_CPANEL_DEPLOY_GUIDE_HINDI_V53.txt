HOSTING COMPATIBILITY
V52 में Node.js + Express application है। इसलिए इसे सामान्य PHP-only hosting में सीधे नहीं चलाया जा सकता। HostyCare की hosting जानकारी में cPanel और Node.js support सूचीबद्ध है; फिर भी आपके खरीदे हुए plan/account में “Setup Node.js App” / “Node.js Selector” उपलब्ध होना जरूरी है। यदि यह option नहीं है तो HostyCare support से Node.js app hosting enablement की पुष्टि करें।

PACKAGE FILES
- package.json: npm start command उपलब्ध है।
- server.js: application entry/startup file; PORT environment variable पर सुनता है।
- public/index.html: website entry file; root index.html fallback भी मौजूद है।
- Code.gs: मौजूदा Google Apps Script backend code — इसे cPanel में Node app के रूप में run नहीं करना है। यह आपके मौजूदा Apps Script project में ही रहता है।
- कोई node_modules folder शामिल नहीं है; cPanel पर npm install चलना चाहिए।

DEPLOYMENT — cPANEL
1. पहले मौजूदा live website, GitHub repository और Google Sheet/Drive/Apps Script का अलग backup रखें। पुराने Railway/Cloud Run deployments को अभी बंद या delete न करें।
2. cPanel में Software section खोलें। “Setup Node.js App” या “Node.js Selector” उपलब्ध होना चाहिए।
3. Node.js version चुनें: उपलब्ध supported version में Node.js 20 या उससे नया (कम-से-कम 18) चुनें।
4. Application mode: Production. Application root: public_html سے باہر ایک الگ folder مثلاً gwc-node-app (مثلاً /home/CPANEL_USER/gwc-node-app). Application URL: اپنا domain یا مطلوبہ subdomain منتخب کریں۔ Startup file: server.js.
5. ZIP को application root میں upload/extract کریں، اس طرح package.json اور server.js application root میں براہ راست ہوں؛ کسی extra nested folder کے اندر نہ رہ جائیں۔ node_modules upload نہ کریں۔
6. cPanel کے Node.js app screen میں Run NPM Install / NPM Install چلائیں۔ اگر terminal استعمال کر رہے ہیں تو app root میں npm install چلائیں۔
7. Environment Variables میں GWC_API_URL نام کا variable بنائیں۔ Value میں اپنے پہلے سے چل رہے Google Apps Script Web App کا مکمل /exec URL دیں۔ اصل URL کو ZIP، GitHub یا public screenshots میں نہ ڈالیں۔ اسے secret رکھیں۔
8. Save/Apply configuration کریں، پھر cPanel کے مطابق Restart Application / Start App دبائیں۔
9. Domain पर /healthz खोलें। JSON में ok:true और websiteEntry public/index.html या index.html दिखना चाहिए। फिर homepage खोलें।

POST-DEPLOYMENT TEST — पुराने production को बंद करने से पहले
- Admin, Teacher, Student और Subadmin के मौजूदा IDs/passwords से login test करें। किसी credential को reset न करें।
- Google Sheets load और non-critical test record save/read test करें।
- Fee records/slips, Homework, Tests, Doubts, Private Notes, Help Desk, Drive uploads (छोटी और 1MB से बड़ी file), Meet links और दो devices पर simultaneous session test करें।
- Browser console तथा cPanel application logs में 4xx/5xx, missing GWC_API_URL, npm errors और memory/process errors देखें।
- सब test pass होने के बाद ही DNS/domain switch करें। पुराने Railway/Cloud Run deployment और उसकी environment settings को rollback अवधि तक सुरक्षित रखें।

SECURITY / DATA SAFETY
- GitHub repository private रखें। ZIP में wrangler.toml और अन्य inherited configuration files हैं; publish करने से पहले उनमें मौजूद endpoint/configuration की समीक्षा करें।
- GWC_API_URL को cPanel Environment Variables में रखें; वास्तविक secret को source code में hardcode न करें।
- Google Apps Script deployment URL, Script Properties, Spreadsheet ID, Drive Folder ID, Sheet data या login records को बिना जरूरत न बदलें।
- cPanel app को public domain पर चलाने का अर्थ केवल website public होना है; Admin/Teacher/Student authentication application के मौजूदा code से ही नियंत्रित रहता है।
- पहले backup/copy और non-critical test records पर जांच करें। Production sheet पर destructive test न करें।

IMPORTANT LIMITATION
यह ZIP deployment-ready source package और निर्देश देता है; यह आपके HostyCare account में स्वयं deploy नहीं हुआ है। HostyCare plan में Node.js feature, Node version, Passenger/Node selector configuration, environment-variable support और resource limits account-specific हो सकते हैं। Live cPanel, Google Apps Script, Sheets, Drive, DNS और end-to-end login testing इस ZIP से नहीं की गई है।
